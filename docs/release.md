# Distribution, associations, and updates (`0.12.0`)

## Local packaging pipeline

```sh
cargo xtask icons          # assets/icons/{16..1024}.png, mdview.ico, mdview.icns
cargo xtask package        # release build + Linux artifacts + checksums + SBOM + manifest
cargo xtask release-check  # verify artifacts, checksums, and required inputs
cargo xtask sbom           # regenerate dist/sbom.cdx.json only
```

`cargo xtask package` writes to `dist/`:

| Artifact | Contents |
|---|---|
| `mdview-<version>-linux-<arch>.tar.gz` | portable Linux tree |
| `mdview_<version>_amd64.deb` | Debian/Ubuntu package with desktop, MIME, AppStream, and hicolor icons |
| `mdview-<version>-1.<arch>.rpm` | RPM package with the same payload and MIME hooks |
| `MD-View-<version>-<arch>.AppDir` | AppImage source tree with `AppRun` |
| `MD-View-<version>-<arch>.AppImage` | built when `appimagetool` is on `PATH` (or an existing AppImage is present) |
| `SHA256SUMS` | SHA-256 for every asset |
| `sbom.cdx.json` | CycloneDX 1.5 component inventory from `cargo metadata --locked` |
| `latest.json` | update manifest with version, notes, asset URL, size, and SHA-256 |

`MDVIEW_UPDATE_BASE_URL` sets the asset base URL written into `latest.json`; the default is a
placeholder until the release host exists.

### Linux install

```sh
sudo dpkg -i dist/mdview_0.12.0_amd64.deb
# or
sudo rpm -i dist/mdview-0.12.0-1.x86_64.rpm
# or
chmod +x dist/MD-View-0.12.0-x86_64.AppImage
./dist/MD-View-0.12.0-x86_64.AppImage
```

The packages install:

- `/usr/bin/mdview`
- `/usr/share/applications/mdview.desktop`
- `/usr/share/mime/packages/mdview.xml`
- `/usr/share/metainfo/org.mdview.MDView.metainfo.xml`
- `/usr/share/icons/hicolor/{16,32,48,64,128,256,512}x*/apps/mdview.png`

The Debian/RPM maintainer scripts refresh the MIME and desktop databases when those tools exist.
Uninstall with `dpkg -r mdview` / `rpm -e mdview`; the association files are removed with the
package.

## Associations

- Markdown (`.md`, `.markdown`, `text/markdown`) is the primary association and the default
  handler candidate. `.txt` remains an opt-in “Open with” choice rather than a forced handler.
- Linux: MIME XML and the desktop entry declare `text/markdown`.
- macOS: `CFBundleDocumentTypes` and an exported `net.daringfireball.markdown` UTI.
- Windows: per-user ProgID `MDView.Markdown` for `.md`/`.markdown`, registered under HKCU by the
  MSI. No administrator rights are required.

## Platform packages

- **Windows:** `packaging/windows/mdview.wxs` is a WiX v4 per-user MSI with a Start-menu
  shortcut, upgrade handling, uninstall, and Markdown associations.
  `packaging/windows/build-msi.ps1` builds it. Authenticode signing is applied by the release
  operator with the organization's certificate; no certificate is stored in the repository.
- **macOS:** `packaging/macos/Info.plist`, `entitlements.plist`, and `build-dmg.sh` produce a
  universal `.app` and `.dmg`. The script expects a Developer ID identity, uses hardened runtime,
  signs, and optionally notarizes/staples with `notarytool`. `mdview.icns` is generated by
  `cargo xtask icons`.
- **Flatpak:** `packaging/flatpak/org.mdview.MDView.json` uses the Freedesktop 24.08 runtime,
  Wayland/X11 fallback, DRI, home access, and the desktop portal. It does not request
  `--filesystem=host`. Build with `flatpak-builder`; the manifest is intentionally not in the
  local `xtask` pipeline because it needs the Flatpak runtime.

## Update flow

**Help → Check for Updates…** reads `[updates] manifest_url` from `config.toml` or the
`MDVIEW_UPDATE_MANIFEST` environment variable.

1. Fetch and parse `latest.json` with a 20-second timeout and 1 MB limit.
2. Compare dotted versions; a newer version opens the update dialog with notes and the matching
   platform asset.
3. Download with a 300-second timeout and 256 MB limit.
4. Verify the SHA-256 before writing the file to the platform cache.
5. Show the verified path with an **Install update** action:
   - **AppImage:** copies the verified file beside the running AppImage, preserves mode `0755`,
     and atomically renames it over the old mount target.
   - **deb:** `pkexec dpkg -i <file>`; **rpm:** `pkexec rpm -U --replacepkgs <file>`.
   - **Flatpak:** `flatpak update -y`.
   - **Windows MSI:** `msiexec /i <file> /passive`; **macOS DMG:** `open <file>`.
   - Unsupported assets remain a manual install with the downloads folder action.
6. After installation, **Restart now** starts a detached waiter that relaunches the new binary
   after the current process exits. Dirty documents block installation until saved or discarded.
   The app never silently replaces its own binary.

If no URL is configured, the dialog explains how to set one. The placeholder manifest URL in
`latest.json` must be replaced by the actual release host before shipping a public update channel.
Package-manager actions that need privilege use `pkexec`; a cancelled authentication prompt is
reported and leaves the downloaded file in place.

## Signing and release gates

The repository does not store certificates, keys, or tokens. A signed release needs:

- Windows Authenticode certificate plus timestamping;
- macOS Developer ID Application identity, hardened runtime, notarization, and stapling;
- GPG key for Debian/RPM repositories and Flathub verification for Flatpak.

`cargo xtask release-check` verifies the local artifact set, SHA-256 values, SBOM, manifest, and
packaging inputs. It does not contact a network or a release host. Hosted CI/CD remains disabled
until the `1.0.0` release gate, as required by `AGENT.md`.
